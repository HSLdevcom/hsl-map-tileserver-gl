# hsl-map-tileserver-gl
Tileserver-gl image with HSL map styles to replace older hsl-map-server service.

# Usage

- Build the docker image:
    ```bash
    docker build -t hsldevcom/hsl-map-tileserver-gl
    ```

- Start the container:
    ```bash
    docker run -p 8080:8080 hsldevcom/hsl-map-tileserver-gl
    ```

# Endpoints

### Vectors
`{host}/styles/{id}/{z}/{x}/{y}` 

### Rasters
`{host}/styles/{id}[/{tileSize}]/{z}/{x}/{y}[@2x].{format}`
- The optional ratio @2x (ex. @2x, @3x, @4x) part can be used to render HiDPI (retina) tiles
- The optional tile size /{tileSize} (ex. /256, /512). if omitted, tileSize defaults to 256.
- Available formats: png, jpg (jpeg), webp

### Styles 
`{host}/styles/{id}/style.json`

# Development

Refer to the `Dockerfile` for turning off automatic `hsl-map-style` style generation as well as automatic OMT data downloading if you're developing tilesets or map styles.

### API Configuration
`config.json` Determines the main configurations of the tile server, as well as datasources that are made available to the styles generated by the `generateStyles.js` script. Using the default configuration,
all of the styles placed in the `styles` folder will be made available in vector and raster format.

### Local tiles
If using other tiles than the ones downloaded from hsldevcom storage, they need to be placed into the `data` folder. Using default configuration the file needs to be named `finland.mbtiles` in order for the tiles to be loaded into the tileserver.

### Styles

Generation of `hsl-map-style` styles can also be done manually without Docker by running these commands:
```bash
yarn install
yarn make-styles
```
